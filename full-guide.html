Deploying to Render (Free Tier)

Get a public HTTPS URL for Apigee to point to

1
Push to GitHub

Create a new GitHub repo and push the entire secure-ai-gateway/ folder to it.

2
Sign up at render.com

Go to render.com → New → Web Service → Connect your GitHub repo.

3
Configure the service

Render auto-detects render.yaml. Set Runtime: Docker. Under Environment Variables, add ANTHROPIC_API_KEY with your key.

4
Deploy

Click Deploy. In ~3 minutes you'll have a URL like https://secure-ai-gateway.onrender.com. Verify with GET /status.

💡
Free tier on Render spins down after 15 min of inactivity (cold start ~30s). For portfolio demos, that's fine. For production, upgrade to the $7/mo paid tier.

Phase 2 — Apigee Setup

Security, traffic control, and response transformation

📋 Step 1 — Sign Up & Create the Proxy

1
Get a free Apigee org

Go to cloud.google.com/apigee → Start Free Trial. You get a free Evaluation org with no billing needed for this project.

2
Create the API Proxy

In Apigee UI: Develop → API Proxies → + Create. Choose "Reverse Proxy". Set:

  • Name: secure-ai-gateway-proxy
  • Base Path: /ai-gateway
  • Target URL: https://secure-ai-gateway.onrender.com
3
Deploy to eval environment

After saving, click Deploy and select the eval environment. Your proxy URL will be: https://YOUR-ORG-eval.apigee.net/ai-gateway

🔐 Step 2 — Add API Key Security (VerifyAPIKey)

Attach this policy to PreFlow → Request in your proxy editor.

<VerifyAPIKey name="VerifyAPIKey-1">
  <APIKey ref="request.queryparam.apikey"/>
</VerifyAPIKey>

Then in Publish → API Products, create a product linked to your proxy and generate an API key. Only requests with ?apikey=valid-key will pass through.

⚡ Step 3 — Spike Arrest (Rate Limiting)

Attach AFTER VerifyAPIKey in PreFlow → Request.

<SpikeArrest name="SpikeArrest-1">
  <Rate>10pm</Rate>  <!-- 10 per minute -->
  <UseEffectiveCount>true</UseEffectiveCount>
</SpikeArrest>
ℹ️
10pm = 10 per minute in Apigee notation. Apigee smooths it to ~1 req/6 seconds. Clients exceeding this receive HTTP 429 Too Many Requests.

🔄 Step 4 — JSON to XML Transformation

Attach to PostFlow → Response. Your Java backend returns JSON — clients receive XML.

<JSONToXML name="JSONToXML-1">
  <Options>
    <ObjectRootElementName>Root</ObjectRootElementName>
    <ArrayRootElementName>Array</ArrayRootElementName>
    <ArrayItemElementName>Item</ArrayItemElementName>
  </Options>
  <OutputVariable>response</OutputVariable>
  <Source>response</Source>
</JSONToXML>

Also add an AssignMessage policy after it to set Content-Type: application/xml.

The XML output will look like:

<Root>
  <request_id>a3f2b1c4-...</request_id>
  <ai_response>1. Independent scalability...</ai_response>
  <tokens_used>312</tokens_used>
  <status>SUCCESS</status>
</Root>

🗺️ Full Proxy Flow Summary

PreFlow → Request:
  1. VerifyAPIKey-1      (reject if no/invalid key)
  2. SpikeArrest-1       (throttle to 10rpm)
  3. FC-CommonLogging    (inject trace headers via Shared Flow)

[Target Endpoint: your Spring Boot on Render]

PostFlow → Response:
  1. JSONToXML-1         (transform body to XML)
  2. AM-SetXMLContentType (set Content-Type: application/xml)

Phase 3 — Shared Flow (DRY Principle)

Reusable infrastructure logic — the "Senior Dev" move

💡
A Shared Flow in Apigee is like a utility function in code. You define reusable policy logic once and call it from any proxy via a FlowCallout. This is DRY at the infrastructure level.

🔨 Creating the Shared Flow

1
Create a new Shared Flow

In Apigee UI: Develop → Shared Flows → + Create. Name it common-logging-sf.

2
Add the AssignMessage policy inside the Shared Flow
<AssignMessage name="SF-AddLoggingHeaders">
  <Set>
    <Headers>
      <Header name="X-Correlation-ID">{messageid}</Header>
      <Header name="X-Apigee-Org">{organization.name}</Header>
      <Header name="X-Gateway-Timestamp">{system.timestamp}</Header>
    </Headers>
  </Set>
  <AssignTo type="request"/>
</AssignMessage>
3
Deploy the Shared Flow

Deploy it to the eval environment — same as your proxy.

4
Call it from your proxy

Back in your API proxy, add this FlowCallout policy to PreFlow → Request:

<FlowCallout name="FC-CommonLogging">
  <SharedFlowBundle>common-logging-sf</SharedFlowBundle>
</FlowCallout>

📈 Why This Impresses Interviewers

  • Shows you understand separation of concerns at the infrastructure level
  • Proves knowledge of DRY principle beyond just application code
  • The X-Correlation-ID header enables distributed tracing across microservices — a real enterprise concern
  • Any other proxy in your org can now reuse this same logging logic with one line

Testing End-to-End

Verify all policies are working

✅ Test 1 — Valid request (should succeed)

curl -X POST \
  "https://YOUR-ORG-eval.apigee.net/ai-gateway/process-data?apikey=YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"input":"Summarize REST APIs","agent_type":"summarizer"}'

Expected: 200 OK with XML body (JSONToXML transformed)

❌ Test 2 — Missing API key (should fail)

curl -X POST \
  "https://YOUR-ORG-eval.apigee.net/ai-gateway/process-data" \
  -H "Content-Type: application/json" \
  -d '{"input":"test"}'

Expected: 401 Unauthorized — API key missing

⚡ Test 3 — Spike Arrest (should throttle)

# Bash loop — fire 15 requests in quick succession
for i in {1..15}; do
  curl -s -o /dev/null -w "%{http_code}\n" \
    "https://YOUR-ORG-eval.apigee.net/ai-gateway/status?apikey=YOUR_KEY"
done

Expected: First ~10 return 200, then you start seeing 429 Too Many Requests

🔍 Test 4 — Check trace headers (Shared Flow)

curl -v \
  "https://YOUR-ORG-eval.apigee.net/ai-gateway/status?apikey=YOUR_KEY" \
  2>&1 | grep "X-Correlation-ID\|X-Gateway-Timestamp"

Expected: Both custom headers injected by the Shared Flow
